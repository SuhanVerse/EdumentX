### 2b. Map pin avatars render inconsistently
Screenshots show pins with photos in one session, default green person-icons in
another. `tracksViewChanges` appears **nowhere** in `src/` (verified by search) —
classic `react-native-maps` custom-marker bug: the native canvas snapshots the
marker before the remote `<Image>` loads and never repaints.

Fix in `src/screens/student/MapSearch.tsx` custom `<Marker>`:
- add `tracksViewChanges` state that stays `true` until the avatar `onLoad` fires
  (then `false`), or
- remount markers via `key={tutor.uid + (tutor.photoUrl ?? "")}`, or
- switch marker image to `expo-image` (already a dependency) which recycles properly.

### 2c. Bucket was flipped PUBLIC — security regression to revert
The user made `private-verification-docs` **PUBLIC** in the Supabase dashboard
trying to fix previews. That was never the bug (the cache-bust was), and it
exposes citizenship/certificate scans of 7 tutors at guessable `{uid}/{kind}.{ext}`
keys. Note: the app **cannot** use public URLs for PII anyway —
`getVerificationDocPublicUrl()` returns `null` for citizenship/certificate kinds
by design, so flipping the bucket accomplished nothing in-app.

Revert in Supabase SQL Editor:

```sql
update storage.buckets set public = false where id = 'private-verification-docs';
```

(Migration `016_private_verification_docs.sql` policies are already in place —
no anon SELECT policy exists — so private flag + signed-URL flow is the intended
end state.)
